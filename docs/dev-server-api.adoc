== Dev server HTTP API (`scripts/dev_server.py`)

Unless noted, routes are intended for *local development* on the same origin as the static app.

[cols="2,1,3",options="header"]
|===
|Route |Method |Purpose

|`/.well-known/lmstudio-dev-server`
|GET
|Probe: app detects bundled LM Studio proxy capabilities.

|`/api/heise-comments`
|GET
|Heise article + forum comment stats (`url` query).

|`/api/article-image`
|GET
|Same-origin proxy for remote article images / thumbnails (`url` query).

|`/api/heise-feed`
|GET
|Proxy for `https://www.heise.de/…/*.xml` feeds (`url` query; allowlisted paths).

|`/api/telepolis-feed`
|GET
|Telepolis Atom proxy.

|`/api/bild-feed`
|GET
|BILD RSS proxy.

|`/api/golem-feed`
|GET
|Golem RSS proxy (shared cache with comment helper).

|`/api/golem-comments`
|GET
|Golem comment count + forum link from RSS (`url` query).

|`/api/t3n-feed`
|GET
|t3n RSS proxy.

|`/api/it-administrator-feed`
|GET
|IT-Administrator RSS proxy.

|`/api/verge-feed`
|GET
|The Verge Atom proxy; optional `url` for section feeds under `https://www.theverge.com/rss/`.

|`/api/computerbase-comments`
|GET
|Stub / metadata for ComputerBase articles.

|`/api/bild-comments`
|GET
|Stub / metadata for BILD articles.

|`/api/t3n-comments`
|GET
|Stub for t3n.

|`/api/verge-comments`
|GET
|Stub / `#comments` link for Verge.

|`/api/source-feed`
|GET
|Registry-backed source feed proxy. Returns RSS built from Bing News search results, verified publisher article pages, or proxied official RSS/Atom, depending on `engine`. Main query params: `engine`, `label`, `site_url`, `lang`, `limit`; optional `id`, `site`, `feed_url`, `rev`, `mkt`. `engine=publisher` requires a configured `id` and matching `site_url`.

|`/api/check-url`
|GET
|HTTP probe for alternative-link validation (`url` query).

|`/api/search-news`
|GET
|Bing News RSS search (`q`, `limit`, `mkt` query params).

|`/api/reddit-search`
|GET
|Reddit thread search JSON proxy.

|`/api/youtube-search`
|GET
|YouTube Data API v3 search if `YOUTUBE_API_KEY` is set.

|`/api/v1/chat`
|POST
|Forwarded to LM Studio chat (same-origin bridge).

|`/v1/models`
|GET
|Forwarded model list (OpenAI-style discovery fallback; usually only model ids, no native reasoning capability metadata).

|`/api/v1/models`
|GET
|Native LM Studio model list proxy with `/api` prefix; includes loaded-state metadata and, when provided by LM Studio, capability fields such as `capabilities.reasoning.allowed_options`.
|===

Also serves static files from the project root (e.g. `index.html`, `js/`, `locales/`).

`/api/source-feed` validates RSS/Atom before caching it. Empty feeds, malformed XML,
and HTML error pages return HTTP 502 (`source_feed_empty` or
`source_feed_invalid_xml`) rather than a successful empty feed. The browser uses
the actual XML format to select its RSS or Atom parser. Publisher requests remain
server-side; these feed changes require no new browser CSP origins.

`engine=publisher` reads explicit profiles from `scripts/publisher_sources.json`.
It discovers candidate links on publisher pages and advertised sitemaps, then
fetches each article to confirm its canonical publisher URL, title, publication
timestamp, public accessibility and readable text. Up to 16,000 characters of
verified plain article text are safely encoded into RSS `description` for the KI
summarizer. Sitemap `lastmod` is never treated as a publication date.
Only configured HTTPS hosts and public network addresses are accepted, including
redirect targets. Requests are bounded to 16 seconds per source and 4 MiB per
document, including decompressed sitemaps. A profile mismatch returns HTTP 400;
unavailable or unverifiable public articles return HTTP 502 with a
`publisher_unavailable:...` reason. No search API key or paid service is used.
