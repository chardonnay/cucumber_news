image::images/cucumber-news-banner-v2.png[Cucumber NewsScraper banner,width=800,align=center]

Multi-source, responsive news dashboard with optional *AI summaries* (LM Studio REST v1, OpenAI-compatible APIs, or Anthropic Messages API), local IndexedDB cache, and a Python dev server for feeds, comments metadata, and same-origin KI proxying. Besides the original tech/news sources (Heise, Telepolis, Golem, ComputerBase, t3n, IT-Administrator, BILD, The Verge), the source catalog now also includes a broad international publisher list in `js/news-sources-registry.js` (for example BBC News, CNN, New York Times, Guardian, Wall Street Journal, Bloomberg, Financial Times, Fox News, Deutsche Welle, Der Spiegel, WELT, Süddeutsche Zeitung, FAZ, Tagesschau, Le Monde, El País, Nikkei, CBC News, ABC Australia, Al Jazeera and many more).

== Quick start (recommended)

[source,bash]
----
cd news_reader_web
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/dev_server.py
# Open http://127.0.0.1:8080/index.html
----

For subsequent starts, run `.venv/bin/python scripts/dev_server.py` from the project directory. The local `.venv` keeps Python dependencies isolated and is excluded from Git.

Verify the environment with `.venv/bin/python -m pip check` and `.venv/bin/python scripts/dev_server.py --help`.

The bundled server serves static files and proxies LM Studio (`POST /api/v1/chat`, native `GET /api/v1/models`, fallback `GET /v1/models`) plus feed and helper routes (see link:docs/dev-server-api.adoc[Dev server API]). Registry-backed sources use the shared `/api/source-feed` route, primarily with official RSS/Atom feeds. For publishers without a working feed, the `publisher` strategy verifies public article pages discovered through publisher links and advertised sitemaps, including publication dates and readable article text. This path uses no paid search API. Remaining search-backed sources use Bing News RSS.

TIP: A full, browser-based user manual — installation, configuration reference, client-side search, and an "Ask the AI" panel — is available at `manual.html`. Open `http://127.0.0.1:8080/manual.html` or use the *Handbuch* link in the app header. Details: <<_interactive_html_manual,Interactive HTML manual>>.

=== Current UI highlights

* The source selector in the header is sorted alphabetically by the visible source label.
* The header offers previous/next source navigation plus a separate favorite-source jump button; favorite sources can be toggled directly next to the active source logo/wordmark.
* The settings dialog controls which sources appear in the header; favorite sources are stored separately from the enabled-source list.
* Category chips are generated dynamically from the loaded articles of the active source. New sources start with all visible categories enabled; only explicit user deactivations are persisted, per source.
* Optional background refresh can prewarm all enabled sources on the chosen interval. The manual *selected sources generation* run opens its own status modal and processes AI summaries, alternative links, and Reddit discovery with progress, cancel, and ETA feedback.

=== KI (LM Studio)

. Start LM Studio local server (e.g. port `1234`).
. Open *KI-Server* in the dashboard: mode *LM Studio REST v1*, base URL `http://127.0.0.1:1234` (no path), model either explicitly selected from the LM Studio list or left on *Automatic* so Cucumber uses the model currently loaded in LM Studio.
. Enable *REST via same page origin* when using `dev_server`, save, reload.
. The *Reasoning* controls are model-aware in LM Studio mode: the UI only shows levels reported by the current model via `/api/v1/models`, disables the toggle for models without reasoning support, and hides the controls entirely in OpenAI-compatible and Anthropic modes.

=== KI (Anthropic)

. Open *KI-Server* in the dashboard and choose *Anthropic Messages API* under *API mode*.
. Use base URL `https://api.anthropic.com/v1`.
. Enter an Anthropic API key. The app calls `GET /v1/models` for the model list and `POST /v1/messages` for summaries; leaving *Model* on *Automatic* uses the first model returned by Anthropic.
. The *Reasoning* controls are hidden in Anthropic mode because this app only sends the standard Messages API fields used here (`model`, `system`, `messages`, `temperature`, `max_tokens`, `stream`).

Details: link:docs/ki-integration.adoc[AI integration guide].

== Plain static server (limited)

[source,bash]
----
python3 -m http.server 8080
----

Without `dev_server`, many `/api/*` routes and same-origin KI proxying are unavailable; some feeds may fail in the browser due to CORS. The new registry-backed international sources depend on `/api/source-feed`, so for the full source catalog `scripts/dev_server.py` is the intended runtime path.
